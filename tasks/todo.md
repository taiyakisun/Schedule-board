# 先頭ドラッグ時のプレビュー位置修正

## 実装計画

- [x] 添付画像と同じ短いリストの先頭ドラッグを実Tkで再現する
- [x] Canvasのスクロール範囲と行座標を調査して原因を特定する
- [x] 短いリストを上端へ維持し、長いリストだけ自動スクロールするよう修正する
- [x] 先頭プレビューと長いリストの自動スクロール回帰テストを追加する

## レビュー

- 原因は、全行が表示領域に収まる短いリストでも、上端ドラッグ時に `yview_scroll(-1)` を実行していたことだった。Tk Canvasは短い内容を表示領域の下端へ寄せるため、行座標が候補範囲外となりプレビューも解除されていた。
- `scrollregion` の内容高がCanvas高以下なら `yview_moveto(0)` で上端を維持し、自動スクロールを行わないようにした。
- 内容がCanvas高を超える長いリストでは、`yview()` にスクロール余地がある方向だけ従来どおり自動スクロールする。
- 添付画像と同じ3親・4行の構成で、末尾の親グループを先頭へドラッグし、プレビュー上端とCanvas上端の差が2px以内であることを実Tkで確認した。
- 45行の長いリストで上下端の自動スクロールが維持される回帰テストも追加した。
- 同梱Tcl/Tkを使った `python -B -m unittest discover -v`: 全67件成功、スキップ・警告なし。
- Ruff、`git diff --check`、UTF-8 BOMなし／LF検査: 成功。

- [x] TODO・タスク間の移動処理から確認ダイアログを撤廃する
- [x] ウィンドウを閉じる操作へ終了確認ダイアログを追加する
- [x] 確認結果ごとの終了動作と、確認なしの相互移動をテストする
- [x] 全テスト・静的検査・EXE再ビルドと起動確認を行う

## レビュー

- 「TODOへ移動」「タスクへ移動」から確認処理を外し、選択グループを即時移動・保存するようにした。
- ルートウィンドウの `WM_DELETE_WINDOW` へ終了確認を登録し、「いいえ」では継続、「はい」では破棄するようにした。
- 相互移動で確認が呼ばれないこと、保存失敗時の復元が維持されること、終了確認の両分岐をテストした。
- 同梱Tcl/Tkを使った全69テスト、Ruff、`git diff --check`に成功した。
- PyInstaller 6.21.0でEXEを再ビルドし、起動継続と重大なビルド警告がないことを確認した。
