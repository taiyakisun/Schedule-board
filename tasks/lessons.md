# Lessons

- ユーザー入力を `float()` へ変換した後は、範囲だけでなく `math.isfinite()` も確認してからモデルを変更する。
- 折りたたみで画面行と保存データの件数が変わるUIでは、配列添字ではなく安定IDで選択対象を追跡する。
- 保存処理ではシリアライズも例外処理の内側に置き、一時ファイルからの原子的置換で既存データを守る。
- Tkの名前付きフォントを派生させるときは、`Font(root, actual_dict)` の位置引数を使わず `Font.copy()` で複製する。位置引数を誤ると、日本語フォントのfamily・sizeが意図せず変わり、文字化けや欠落につながる。
- TkのFrameで `grid_propagate(False)` を使って幅を固定すると高さの自動計算も無効になる。文字領域を1pxに潰さないよう、行コンテンツのheightも必ず明示し、実ウィジェット寸法で確認する。
- 短い値が多い情報列を固定の広い幅にしない。最小幅を小さくし、実データの表示文字列をフォントで計測して必要な場合だけ上限まで拡張する。
- 階層データのExcel出力では親名を子行へ反復せず、1つのツリー列へ開閉記号・枝線・インデントを集約する。列幅を縮める場合は、長い日本語タイトルに合わせて行高も自動調整し、画像で文字切れを確認する。
- TkのCanvasを狭い情報列へ追加するときは `width` を明示する。既定要求幅のままgridへ置くと、minsizeよりCanvasの要求幅が優先され、ヘッダーと行の列境界が大きくずれるため、実座標で両方の開始位置を検証する。
- Windowsの `CopyFromScreen` は背面ウィンドウを黒く取得する場合がある。外観検証では対象を前面へ出して再描画を待ち、Tkの実座標・ウィジェット色テストと画像の両方で判断する。
- Tkの `StringVar.trace_add()` はウィジェット破棄だけでは監視コマンドが残り得る。trace IDを保持し、成功・キャンセル・Escape・WM_DELETEを共通closeへ集約して `trace_remove()` してから破棄する。
- 日付スケールはデータ件数ではなく画面のピクセル解像度を上限に描画する。全月を列挙して同じx座標へ重ねず、表示幅から年・月stepを算出してCanvasアイテム数を制限する。
- 一時ファイルへの書き込みと `os.replace()` だけでは、電源断時の媒体確定までは保証できない。`flush()`、`os.fsync()`、1世代バックアップ、起動時復旧までを一組として設計する。
- 複数ファイルを更新する完了処理は、書き込み順だけでは停止タイミングによる不整合をなくせない。先にジャーナルを同期保存し、再実行を冪等にして次回起動時に完了できるようにする。
- シンプルさを掲げるUIでは、要素を増やすより周辺UIの彩度と罫線を抑え、主作業領域・主要操作・状態表示の優先順位を明確にする。
- Tkの `iconphoto(..., default=True)` と `iconbitmap(default=...)` は将来のトップレベル用の既定設定であり、現在のメインウィンドウへ確実に適用するには `default=False` の `iconphoto` と引数指定の `iconbitmap` も呼ぶ。
- 画面切替とデータ操作を同じボタン表現・色・近接配置にしない。主ナビゲーションは選択下線などのタブ表現で独立させ、関連操作はメニューへまとめて役割と優先度を明確にする。
- Canvas内で複数段の文字を固定座標へ置かない。各フォントの `linespace` と利用可能高から段ごとの上端・下端を計算し、アンカー方向も揃えて文字領域が交差しないことをテストする。
